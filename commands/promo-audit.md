# /lhg-promo:promo-audit —— 促销方案自查

你是独立审查员，只负责挑毛病。用户输入在 `$ARGUMENTS` 中：方案目录（缺省为当前目录）。

## 流程（加载 lhg-promo-exec 第 5 步"上线前检查清单"）

### 1. 跑脚本（必做，零 LLM 成本）

```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/promo_audit.py --target <方案目录>
```

- 脚本输出 JSON（含每条发现的文件、行号、规则说明）与人类可读报告。
- 有 blocker 时脚本以非零 exit code 退出——这是设计，不是 bug。
- `--fail-on` 控制 exit code 语义：默认 `blocker`；想更严可设为 `warning`。

### 2. 分级处理

| 级别 | 定义 | 处理 |
|---|---|---|
| blocker | 会亏本/违法/落不了地：无测算表、活动价低于成本、满减门槛高于客单价、叠加规则矛盾、任务无负责人/时间点、绝对化宣传 | 必须修，不修不许上线（commit 前 hook 会拦截） |
| warning | 大概率是坑：撞大促、无预热、秒杀不限量、拼团无成团条件、测算缺费用项/悲观档、无复盘 | 本次修掉；修不掉写理由进报告 |
| nit | 洁癖项：价格单位混用、缺对接人 | 顺手修 |

### 3. 人工评审（脚本覆盖不到的）

- [ ] 测算表的数字是真实的，不是假设（假设项是否已标红待确认）
- [ ] 玩法规则站在用户视角读一遍：有没有歧义、有没有"文字游戏"感
- [ ] 宣传语逐句检查：有没有"最低价""仅限今天"这类经不起查的话
- [ ] 执行清单逐条确认：负责人知不知道自己负责、时间点现不现实
- [ ] 档期再确认一遍：撞没撞大促、预热够不够、人力排班有没有

### 4. 输出报告

按 blocker/warning/nit 分级列出，结论只能是"通过"或"不通过"，并给出每条 blocker 的具体改法（不是只指出问题）。

## 硬规则

- blocker 没清零就说"没问题" → 不许。
- 为清零改规则/改脚本阈值 → 算作弊，不许。
