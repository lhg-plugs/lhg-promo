# lhg-promo-exec：促销执行与复盘

> 目标：让策划 100% 落地，活动结束有复盘可沉淀。
> 核心纪律：**任务三件套（事项/负责人/时间）缺一不可；上线前检查清单逐项打勾。**

## 1. 何时使用

- 测算通过，要排执行 → 第 2~3 步
- 活动前一天/当天 → 第 5 步上线前检查清单
- 活动结束 → 第 4 步复盘模板
- 执行中出问题 → 第 3 步风险预案启动条件

## 2. 输入与输出

**输入**：通过测算的《玩法设计稿》+《档期表》。

**输出**：《执行清单》（倒排任务表）、《物料与预算表》、《风险预案》、《复盘模板》四份文档。

## 3. 分步方法论

### 第 1 步：倒排任务（从开卖日往回排）

以"开卖时刻"为 T0，倒排所有任务。每条任务 = **事项 + 负责人 + 截止时间**，三件套缺一不可：

```markdown
- [ ] 满减规则后台配置 负责人：小王 截止：T-3
- [ ] 活动海报设计定稿 负责人：小李 截止：T-5
- [ ] 短信/推送文案审核 负责人：小张 截止：T-2
- [ ] 客服话术培训 负责人：小赵 截止：T-1
```

**排期技巧**：关键路径上的任务（系统配置、物料设计）截止时间再提前 1 天，留 buffer。负责人必须是具体的人，不能写"运营部"。

### 第 2 步：物料与预算表

物料清单：海报、详情页、直播脚本、短信/推送文案、私域话术、客服问答——每项标注"设计/审核/上线"三个状态。预算总表：推广费、物料制作费、人力成本、赠品/券成本汇总，**总数要和测算表对得上**，对不上说明有漏项。

### 第 3 步：风险预案（至少 2 条，写清触发条件）

预案不是"到时候再说"，每条预案 = 触发条件 + 应对动作 + 负责人：

| 风险 | 触发条件 | 应对 | 负责人 |
|---|---|---|---|
| 流量不及预期 | 首日 UV < 预期 50% | 加投/私域加推 | __ |
| 超卖/库存不足 | 库存 < 日销×2 | 下架秒杀款/限购 | __ |
| 系统/配置错误 | 规则测试不通过 | 回滚+手工补券 | __ |
| 竞品截胡 | 竞品同品更低价 | 启动备用券 | __ |

### 第 4 步：复盘模板（活动结束 3 天内填）

```markdown
## 促销复盘（活动名+日期）
- 目标达成率：GMV __% / 订单量 __% / 利润 __%
- 三维度分析：流量（预期vs实际，差在哪）/ 转化（哪个玩法贡献最大）/ 利润（测算偏差在哪一行）
- 踩坑记录：发生了什么 / 为什么 / 下次怎么避
- 可复用资产：这次验证有效的玩法/话术/人群包
- 下次改进：只列 3 条，多了等于没列
```

**复盘纪律**：对事不对人，先谈系统问题再谈个人。测算偏差重点看：是假设错了（转化率假设过高），还是执行歪了（预热没做足）。

### 第 5 步：上线前检查清单（开卖前逐项打勾）

- [ ] 确定性审计脚本 0 blocker（`promo_audit.py` 已跑）
- [ ] 玩法规则在测试环境走完一遍（下单/满减/券核销全链路）
- [ ] 宣传语逐句检查：无"全网最低价"、限时话术有明确截止日期
- [ ] 库存/限量配置与方案一致（秒杀款限量已锁）
- [ ] 客服话术已培训，能回答"能不能叠加""什么时候发货"
- [ ] 监控看板就绪：实时 GMV/订单量/保本日销进度
- [ ] 风险预案负责人知晓触发条件

**有一项没打勾就不开卖。** 开卖后再发现问题，成本是现在的 10 倍。

### 执行时间轴示例（T0=开卖日，照着排）

| 时间 | 事项 | 负责人 | 状态 |
|---|---|---|---|
| T-7 | 玩法终稿确认、测算表定稿 | 运营负责人 | ☐ |
| T-5 | 海报/详情页设计定稿 | 设计 | ☐ |
| T-3 | 后台规则配置（满减/券/秒杀） | 运营执行 | ☐ |
| T-3 | 预热开始（加购有礼/种草内容） | 内容 | ☐ |
| T-2 | 短信/推送文案审核、客服话术培训 | 客服主管 | ☐ |
| T-1 | 全链路测试（下单→满减→核销→发货） | 运营执行 | ☐ |
| T-1 | 库存/限量锁定、风险预案负责人确认 | 仓储/运营 | ☐ |
| T0 | 开卖、监控看板值守 | 全员 | ☐ |
| T+1 | 首日复盘快会（数据vs预期，决定是否启动预案） | 运营负责人 | ☐ |
| T+3 | 活动结束 3 天内输出复盘报告 | 运营负责人 | ☐ |

**排期红线**：T-1 的全链路测试不许跳过。90% 的"规则配错"都是没测试直接开卖。用测试账号真实走一遍下单，10 分钟，能省掉开卖后的大混乱。

### 客服话术准备（最容易被遗忘的一环）

活动前客服必须能脱口而出回答：

1. "这个券能和满减一起用吗？"→ 按方案叠加规则一句话回答
2. "秒杀什么时候开始？有几件？"→ 时间+限量
3. "什么时候发货？"→ 明确天数，节假日顺延要说清
4. "能退货吗？"→ 按店铺日常政策，不许为活动临时改

准备一份《客服问答 10 条》文档，T-2 培训完，T-1 抽查。客服答不上来，开卖后咨询量会爆炸。

## 4. 反模式

- **任务没负责人**："大家一起跟"等于没人跟。对策：三件套硬性要求。
- **预案写空话**："加强监控"不是预案。对策：触发条件+应对动作+负责人，三者缺一不可。
- **复盘变批斗**：复盘会开成追责会，下次没人说真话。对策：先谈系统，再谈个人；只列 3 条改进。
- **跳过上线检查**："应该配好了吧"——开卖后才发现券门槛配错。对策：第 5 步逐项打勾，测试环境走一遍。
- **复盘不沉淀**：复盘完文档扔一边。对策：可复用资产单独存档，下次策划先翻。

### 小团队分工表（3~5 人团队照抄）

| 角色 | 负责 | 关键交付 |
|---|---|---|
| 运营负责人 | 目标卡、档期、预案决策 | 目标卡签字、首日复盘会 |
| 运营执行 | 规则配置、数据监控、重算 | 后台配置截图、全链路测试通过 |
| 设计 | 海报/详情页/直播视觉 | T-5 定稿 |
| 客服主管 | 话术培训、咨询承接 | 《客服问答10条》、T-2 培训完成 |
| 仓储/物流 | 备货、盘点、发货时效 | 备货量确认、节假日值班表 |

**一人身兼多职时**：把表打印出来，每行写上同一个名字也行——重点是"每件事都有主"，而不是"人多"。小团队最大的坑是"以为对方会做"，分工表就是用来消灭"以为"的。

## 5. 自检与反馈

**质检门**：

- [ ] 执行清单每条任务都有事项/负责人/截止时间
- [ ] 物料清单每项有设计/审核/上线状态
- [ ] 预算总数与测算表对得上
- [ ] 风险预案 ≥2 条，每条有触发条件+应对+负责人
- [ ] 复盘模板已生成（含目标达成率/三维度/踩坑/资产/改进）
- [ ] 上线前检查清单 7 项可逐项打勾

**标准冒烟用例**：输入一份通过测算的玩法稿，应输出四份文档，且执行清单中每条任务都带负责人和截止时间；缺任何一项应明确标出"待补充"而不是跳过。

**反馈**：发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-promo/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。
