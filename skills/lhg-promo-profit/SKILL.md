# lhg-promo-profit：促销利润测算

> 目标：开卖前就知道"最好赚多少、最坏亏多少、卖多少单才不亏"。
> 核心纪律：**不算账不开卖；红线项直接叫停，没有"先上线看看"。**

## 1. 何时使用

- 玩法设计稿已出，要算能不能做 → 全流程
- 用户说"力度再大点"→ 重算，看是否击穿利润底线
- 活动进行中要调价 → 只重算受影响的行
- 复盘 → 对照测算表看偏差，见 lhg-promo-exec

## 2. 输入与输出

**输入清单**（向用户要，拿不到就标"假设"）：

| 类别 | 要什么数字 |
|---|---|
| 商品 | 成本（含赠品成本）、日常售价、活动价 |
| 历史 | 客单价、转化率、流量（自然流/付费流分开） |
| 玩法 | 满减门槛与力度、优惠券面额×发放量、秒杀款成本×限量 |
| 费用 | 推广费、平台佣金率、物流成本/单、人力成本 |

**输出**：《利润测算表》：列=乐观/中性/悲观三档，行=收入-成本-费用-利润全链路，外加保本点。结论三选一：能做 / 调完再做 / 别做。

## 3. 分步方法论

### 第 1 步：先定假设，再算数

每个数字标注来源：历史数据 / 平台均值 / 拍脑袋。拍脑袋的数字用**保守值**（转化率取历史下限，核销率取行业下限）。**假设清单单独列出来**，让用户逐条确认——测算最大的坑不是算错，是假设错了还不知道。

### 第 2 步：建表（行一个不能少）

```
预计流量 × 转化率 = 订单量；订单量 × 客单价 = 销售收入
销售收入
- 商品成本（订单量 × 单件成本）
- 赠品成本（注意：赠品是真金白银，单列一行）
- 满减让利（预估达门槛订单占比 × 平均让利）
- 优惠券核销（发放量 × 预估核销率 × 面额）
- 推广费 - 平台佣金（收入 × 佣金率） - 物流成本（订单量 × 单均物流）
= 活动利润 / 利润率
```

**常见漏项**（逐项检查）：赠品成本、优惠券核销（不是发放量，是核销）、退货损耗（按历史退货率计提）、人力加班成本。

### 第 3 步：三档测算

- **乐观档**：流量/转化率取历史大促峰值
- **中性档**：取日常均值 × 1.2~1.5
- **悲观档**：销量打 5~7 折——这是保命档，看最坏亏多少

只算乐观档的测算表是废纸。悲观档亏损超过利润底线 → 直接出"别做/调完再做"结论。

### 第 4 步：算保本点

保本销量 = 固定投入（推广费+人力+物料）÷ 单均毛利。保本点有两个用处：一是判断目标现不现实（目标销量 < 保本点 → 目标必调），二是活动中实时监控（首日销量/保本日销 <0.5 → 启动预案）。

### 第 5 步：红线检查（命中即叫停）

1. **活动价 < 成本价**：每卖一单亏一单。唯一例外是限量亏本引流款（限量+预算上限+明确引流目标），否则叫停。
2. **满减门槛 > 客单价**：门槛形同虚设，用户够不着。降门槛或换玩法。
3. **悲观档击穿利润底线**：先降力度（减档位、降券面额、缩限量），再重算。
4. **费用项缺失**：推广费/佣金/物流少任何一项 → 打回补上，不许"先出结论"。

### 第 6 步：出结论（三选一，不许含糊）

- **能做**：三档皆赚，或悲观档亏损在利润底线内 → 给出关键监控指标（保本日销、核销率上限）
- **调完再做**：列出必调项（具体到数字，如"满减门槛从 200 降到 120"），调完重算
- **别做**：怎么调都亏，或目标销量远超能力 → 直接说别做，并给出替代方案（如改清仓特卖、改拉新目标）

### 测算表示例（数字是编的，格式照抄）

假设：成本 22/件，活动价 29.9（秒杀限量 500 件）+ 满 100 减 10，客单价 150，推广费 5000，佣金 5%，物流 8/单。

| 行 | 中性档 | 悲观档（×0.6） |
|---|---|---|
| 预计流量 | 20000 UV | 12000 UV |
| 转化率 | 3% | 2% |
| 订单量 | 600 单 | 240 单 |
| 客单价 | 150 元 | 140 元 |
| 销售收入 | 90000 | 33600 |
| - 商品成本 | 13200 | 5280 |
| - 满减让利 | 6000 | 2400 |
| - 推广费 | 5000 | 5000 |
| - 平台佣金 | 4500 | 1680 |
| - 物流成本 | 4800 | 1920 |
| = 活动利润 | 57000 | 17320 |
| 保本销量 | 1200 单（含固定投入口径，见第 4 步） | — |

**读表要点**：先看悲观档赚不赚钱，再看保本销量现不现实（600 单中性 vs 保本 1200 单 → 这个例子中性档其实没保本，目标要调——这就是测算的价值：开卖前发现目标定高了）。

### 假设清单模板（单独一页，用户逐条确认）

```markdown
## 测算假设清单（待确认）
- [ ] 转化率 3%：依据去年双11数据；悲观档按 2% 计
- [ ] 流量 20000 UV：自然流 12000 + 投流 8000（投流费用已计入推广费）
- [ ] 满减达门槛订单占比 60%：依据日常满减活动数据
- [ ] 优惠券核销率 30%：行业常见 20~40%，取中值
- [ ] 退货率 5%：按历史均值计提
```

**确认方式**：把清单发给用户，一条条问"这个数你认吗"。不认 → 换他的数重算。认了 → 他签字（哪怕是口头），复盘时偏差复盘有依据。

## 4. 反模式

- **只算乐观档**："大促流量肯定爆"——爆了是惊喜，不爆是常态。对策：三档必做，悲观档是底线。
- **漏费用项**：不算佣金、不算物流、不算赠品——利润虚增。对策：第 2 步漏项清单逐项勾。
- **拿假设当事实**：拍脑袋的转化率写进表就不标了。对策：假设清单单独列，用户逐条确认。
- **红线讨价还价**："活动价低于成本就这一次"——没有"就一次"，亏钱的单量越大亏得越多。对策：红线没有例外，除了限量引流款。
- **测算一次管全程**：活动中流量不及预期不重算。对策：首日数据出来后重算一次，不及预期 50% 启动预案。

### 活动中重算（首日数据出来后必做一次）

首日收盘后，用真实数据替换假设，重算一次中性/悲观档：

1. 真实流量、真实转化率、真实客单价填进去。
2. 对比：实际利润 vs 测算中性档，偏差超过 30% → 找出偏差最大的那一行（通常是转化率或核销率）。
3. 决策：首日销量 < 保本日销×0.5 → 启动风险预案（加投/加推/备用券）；首日销量 > 预期 1.5 倍 → 检查库存是否够用，不够立即限购。

**测算不是一次性工作**。开卖前的测算是"计划"，首日重算是"纠偏"，复盘时的对照是"学习"。三次算完，一个完整的测算闭环才算走完。

## 5. 自检与反馈

**质检门**：

- [ ] 输入清单 4 类数字齐全，缺的标了"假设"并经用户确认
- [ ] 测算表行齐全（含赠品/核销/退货/人力，无漏项）
- [ ] 乐观/中性/悲观三档都有数
- [ ] 保本点已算出
- [ ] 红线 5 项逐项检查，有结论记录
- [ ] 最终结论是三选一之一，不含糊

**标准冒烟用例**：输入"成本 22、秒杀价 19.9 不限量"，应直接出"别做"结论（活动价低于成本价且不限量），而不是给优化建议。
